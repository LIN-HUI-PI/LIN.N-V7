# NELUUN V9.5 — Cloudflare 隔離測試環境操作單（2026-11-01）

## 目的與界線
建立專用 Cloudflare Worker `neluun-v95-auth-test` 和全新 D1 `neluun-v95-auth-isolated-test`。
**不可連接既有 V7／V9.4 正式 Worker 或 D1。此文件及程式只為測試版。**

## 帳號持有人一次性操作（先完成 D1，暫不公開啟用登入）
1. Cloudflare Dashboard → D1 SQL Database → Create database。
2. 名稱輸入 `neluun-v95-auth-isolated-test`，位置可選 Asia-Pacific。
3. 創建後先不要自行清除資料或匯入正式資料，也不要分享密鑰、登入 Cookie、API Token。

## 已準備好的 GitHub 檔案
- `scripts/prepare_v95_worker.mjs`：檢查測試專用資料庫 ID、限定 CI 分支、生成獨立 V9.5 前端資源與 Worker 設定，不修改 V9.4 的 `public/index.html`。
- `.github/workflows/neluun-v95-cloudflare-preflight.yml`：只做合成 ID 的建置測試，**不會部署**。
- `src/v95_parent_api.js`：既有登入 + 家長二次驗證，進入成人敏感 API 前伺服器驗權。
- `migrations/0001_init.sql`、`migrations/0002_parent_access.sql`：新的測試 D1 依序套用。不可套用至現有正式資料庫。

## 第二批：在 D1 建立完成、測試檔驗證後才做
在 Cloudflare Workers & Pages 新建**獨立** Worker `neluun-v95-auth-test`，綁 GitHub `LIN-HUI-PI/LIN.N-V7` 的**測試分支** `neluun-v9-5-safety`。Cloudflare Workers Builds 支援指定 repository / branch 和自訂建置部署命令。

Workers Builds 設定：
- Repository: `LIN-HUI-PI/LIN.N-V7`
- Branch: `neluun-v9-5-safety` （不可用 main）
- Root directory: GitHub repo root
- Build command: `node scripts/prepare_v95_worker.mjs`
- Deploy command: `npx wrangler deploy --config wrangler.v95.generated.jsonc`
- Build variable (非密鑰)：`NELUUN_V95_TEST_D1_ID`，值是剛建立的**測試 D1** UUID（只在 Cloudflare 設定，不需傳給聊天或 GitHub）
- Worker name: `neluun-v95-auth-test`

**注意：Workers Builds 的 Deploy 命令會真的部署這個新測試 Worker；不要在正式 Worker 的設定頁輸入上述配置。**

剛部署時 `PARENT_STEP_UP_ENABLED=false`、`AI_ENABLED=false`、AI 總額度 0；登入和家長驗證會在尚未完成 D1／Secrets 前保持關閉，不得因此認定測試成功。隨後由擁有者在 Cloudflare 設定寄信網域和必要 Secrets（RESEND_API_KEY、EMAIL_FROM、SESSION_PEPPER、OTP_PEPPER），不能提交進 GitHub。

**遷移／驗證需分批：** 先確認測試 D1 ID，單獨執行新庫遷移；再開通寄信與測試用成人帳號；最後才允許測試環境 `PARENT_STEP_UP_ENABLED=true`，並針對成人區、兒童模式、解鎖與撤銷執行真實 E2E。
