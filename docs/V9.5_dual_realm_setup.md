# NELUUN V9.5 — 雙入口（Adult Worker / Child Worker）設定單

分支：`claude/dual-entry-realms`（由 `neluun-v95-dual-entry` 延伸）。不動 main、V7、V9.4。

## 架構
- Adult Worker `neluun-v95-auth-test`：既有 email 登入、parent step-up，新增 `/api/family/*` 與 `public/family.html`。
- Child Worker `neluun-v95-kids-test`：獨立 origin，只有 `/api/kids/*` 與 `kids-public/`，無 email、無 AI、無付款。
- 兩者共用同一個測試 D1 `neluun-v95-auth-isolated-test`；新增資料表 `children`、`child_entry_codes`、`child_sessions`（`migrations/0003_family_children.sql`）。
- 孩子進入流程：adult step-up 通過 → 家長建立孩子檔案（暱稱 + 頭像）→ 家長選 30/45/60 分鐘並產生 8 位數一次性代碼（10 分鐘內有效）→ 孩子在 Child Worker 輸入代碼 → 取得限時 session（cookie `neluun_kid`，上限 60 分鐘）。
- Child session 與 adult session 分表、分 cookie 名稱、分 hash 網域；Child Worker 不提供任何 adult API，Adult Worker 不提供 `/api/kids/*`。
- 家長可隨時結束陪同或刪除孩子檔案；撤回 guardian declaration 會立即使所有孩子 session 與代碼失效。
- `/learn` 由 Child Worker 在驗證 session 後才提供（`run_worker_first: true`），頁面每 30 秒回查，時間到自動離開。

## 為何一直顯示「家長二次驗證尚未啟用」
`scripts/prepare_v95_worker.mjs` 每次部署都把 `PARENT_STEP_UP_ENABLED` 寫成 `"false"`，覆蓋 Dashboard 的值。現在改由 Build variable `NELUUN_V95_PARENT_STEP_UP` 決定（只有值為 `true` 才開啟）。

## 操作順序
1. 將 `claude/dual-entry-realms` 合併到 `neluun-v9-5-safety`（Workers Builds 只接受此分支）。
2. 在測試 D1 Console 執行 `migrations/0003_family_children.sql` 全部內容（0001、0002 已存在）。
3. Adult Worker → Settings → Build → Build variables：新增 `NELUUN_V95_PARENT_STEP_UP` = `true`。保留 `NELUUN_V95_TEST_D1_ID`。重新部署。
4. 確認 Adult Worker Secrets 皆存在：`RESEND_API_KEY`、`SESSION_PEPPER`、`OTP_PEPPER`；`EMAIL_FROM` 為變數。
5. 新建 Worker `neluun-v95-kids-test`，連 GitHub `LIN-HUI-PI/LIN.N-V7`，分支 `neluun-v9-5-safety`：
   - Build command：`node scripts/prepare_v95_worker.mjs kids`
   - Deploy command：`npx wrangler deploy --config wrangler.v95.kids.generated.jsonc`
   - Build variable：`NELUUN_V95_TEST_D1_ID`（同一個測試 D1 UUID）
6. Child Worker Secrets：`OTP_PEPPER`（**必須與 Adult Worker 完全相同**）、`SESSION_PEPPER`（可不同）。
7. 驗收：成人登入 → `/family.html` → step-up → 聲明 → 新增孩子 → 開始陪同 → 孩童網址輸入代碼 → `/learn` → 結束陪同後孩子被登出。

## 已知限制
- 兩個 Worker 共用同一 D1，隔離靠程式邏輯與獨立 origin，不是資料庫層權限。
- Email 驗證只證明信箱控制權，guardian declaration 是自行聲明，不是法定監護人身分驗證。
- `kids-public/learn.html` 內含本機「家長學習紀錄」頁，未加鎖；紀錄只存在該裝置。
- 孩童 AI 維持關閉（`/api/kids/chat` 一律 403），待模型廠商、同意流程與過濾機制確定後再接 AI gateway。
- 孩童網址由 workers.dev 主機名推導（`neluun-v95-kids-test.<帳號>.workers.dev`）；自訂網域需修改 `public/family.html` 與 `public/dual-entry-preview.html`。
- 真機 E2E（信箱寄送、跨裝置、返回鍵、重開）尚未執行。
